# 多 Agent 开发八条铁律

> **功能定义验收，目录定义写权；总控只调度，Worker 只在自己的轨道交付。**

1. **总控只编排，不写业务代码。** 总控 Agent 负责理解全局、冻结基线、拆任务、派发、追踪、决策和组织集成，不代替 Worker 修改业务目录。
2. **按目录所有权分轨，不按功能分人。** 一个功能可以拆给多个轨道，但任何文件在同一开发纪元只能有一个合法写入者。
3. **先冻结契约和基线，再开始并行。** 所有并行 Worker 必须从包含当前契约的同一个 `BASE_SHA` 出发；契约变化就停止派发，形成新 Epoch 后再恢复并行。
4. **一轨一 Worktree、一分支、一会话。** Agent 会话与 Worktree、分支、轨道身份绑定，不切分支、不借用其他轨道会话、不共享可变工作区。
5. **跨轨需求只走 Handoff、RFC 或 Decision Gate。** Worker 可以读取全仓库，但只能写自己的允许路径；需要其他轨道变更时发请求，不直接代改。
6. **小步提交，远端 SHA 才算完成。** 每个可验证增量立即 `commit + push`；已推送历史只追加修复或 `revert`，禁止 amend、rebase、force push。
7. **机器门禁高于提示词自律。** 本地 Hook、总控验收和 CI 同时检查分支、目录范围、任务范围、提交信息、测试、构建和敏感文件。
8. **唯一集成者合并，保留完整证据链。** Worker 不自行合并；集成轨负责组装和发布。全过程保留 Plan、Run、Task、Dispatch、分支、Commit、测试和 Release Manifest。

## 记忆公式

**一总控、五隔离、四门禁、两闭环、一证据链。**

- 一总控：唯一全局调度者。
- 五隔离：目录、Worktree、分支、会话、权限上下文。
- 四门禁：范围、契约、质量、发布。
- 两闭环：跨轨 Handoff 闭环；完成—验收—集成闭环。
- 一证据链：从目标到发布 SHA 全程可追溯。
