# Three-Minute Demo Script

Run the offline acceptance gate and prepare a clean demo database using
[`RUNBOOK.md`](RUNBOOK.md) before presenting. Do not perform a live refresh on
the critical path.

## 0:00–0:25 — Private behavioral signals

**Action:** Enter the demo account and open **My Tags**.

**Say:**

> RealTags starts with behavior signals that remain visible only to the signed-in
> person. This offline walkthrough uses clearly labeled synthetic Fixture data.
> If a Public Live snapshot is shown in an assembled candidate, it is a bounded
> public-profile read and does not prove that this person owns the profile.

**Show:** self-only boundary, provenance labels, and the tag count. Do not call
Fixture rows live, verified-account data, or real-user data.

## 0:25–0:50 — Source ledger and failure behavior

**Action:** Open **Connections**. Point out the Public Live-capable, Fixture, and
Unavailable cards. Do not submit a Public Live refresh while offline.

**Say:**

> The server owns each source mode. A refresh failure keeps the prior snapshot
> and records a bounded state; it never turns a failed live request into a
> Fixture. Keep is demo-only Fixture, while unsafe or unsupported sources have
> no active control.

If the integrated candidate does not show all three classes, stop and record a
failed assembly gate instead of improvising the claim.

## 0:50–1:20 — Anonymous match

**Action:** Start matching, wait for the server-owned result, and open it.

**Say:**

> The decision surface is intentionally narrow: one presentation-smoothed
> percentage and a hidden common-point count. The page does not expose profile
> details, source handles, raw scores, or weights.

## 1:20–2:05 — Conversation and progressive reveal

**Action:** Open the anonymous conversation. Send a short message, use dice,
draw a task card, unlock a common point, and use the demo-only progression
control until L4.

**Say:**

> The server generates shared system cards, so the browser cannot invent an
> unlock. The accelerated control is Fixture behavior for the presentation;
> natural multi-day progression is not being claimed from this three-minute run.

## 2:05–2:40 — Formed group meal

**Action:** Open the formed merchant event and enter its group conversation.

**Say:**

> The event is restricted to the restaurant allowlist and the group still uses
> anonymous aliases. The displayed merchant benefit and manual redemption code
> are Fixtures; they do not represent a partner, payment, POS integration, or
> real redemption.

## 2:40–3:00 — Close on evidence, not aspiration

**Action:** Return to **Connections** or **My Tags**.

**Say:**

> The tested product value is the private-signal-to-anonymous-conversation path.
> Public Live, Fixture, Unavailable, and Roadmap are deliberately separated. We
> are not claiming account ownership, production readiness, persistent service,
> users, revenue, performance metrics, or a judging result. The public URL is a
> resettable hackathon demo.

## Offline contingency

- Keep networking disabled and skip Public Live refresh.
- Use only the reset demo database and local Flask server.
- Never relabel Fixture data to cover an upstream failure.
- If the local path fails, stop the demo and record the failed gate; do not use
  screenshots as runtime evidence.
